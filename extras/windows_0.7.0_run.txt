notes:
 * 'memory 64x/8x less' in each title (bit1 first, then bit8) is an estimate for the array itself, list size divided by bitarray size: a list holds
   an 8-byte pointer per element (this test data shares one object each for 0 and 1), a 1-bit array 1 bit, an 8-bit array 1 byte.
   A list of distinct numbers also needs one 48-byte object per element, about 56 bytes each, so the saving would be larger.
 * One machine, one run of the program; the same command often varies by 30% between runs.  Treat differences under about 2x as noise.
 * lrange and lreverse on a plain list are lazy in Tcl 9.1 (a shared slice, a reversed view), so they cost almost nothing until the
   result is used; a bitarray makes a real copy.  See performance_analysis.md section 2.
 * 'cold' rows start from a fresh array for every call and time only the call.  For a bitarray they include building the list of
   element objects that the core asks for when a command treats it as an ordinary list; that list is kept until the array is next
   changed, so a second call on the same unchanged array is faster ('warm').
 * '2 in $X (miss)' has no ratio (n/a): a 1-bit array answers at once for a value it cannot hold, so the comparison would only measure that shortcut; a plain list has to look at every element.
 * The other 'in' rows have ratios: a 1-bit array tests whole words and stops at the first one that settles the answer (hit at 0 stops at once, hit at the last element and the all-1s miss read every word).
 * 'ledit (shared: copies)' is what a loop sees when another variable holds the same value; 'in place' is the unshared case.
 * lappend, lset and the in-place ledit rows work on a private copy and repeat the call; lappend is amortised (the array doubles).
 * 'create from text': both start from the same fresh string of values.  The plain list is made by parsing it (llength forces the
   string to become a list); newfrom parses it the same way and then also range-checks and packs every element.  Assigning an
   existing list (set a $L) just shares it and costs almost nothing, so that is not a fair comparison.
 * lassign: the first row is the usual use (take a few elements, here from the middle, into variables). The second names three
   variables for the first three elements of the whole array and returns the rest as its result; the core skips building that
   rest when the result is unused (a loop or proc body), so the row shows only the cost when it is used, which is rare.
 * lrepeat is also lazy in Tcl 9.1 (a repeated-list view), which is why plain 'create' is so cheap.
